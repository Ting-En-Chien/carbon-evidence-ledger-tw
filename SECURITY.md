# Security Policy

Carbon Evidence Ledger is an educational prototype and portfolio project. It
is not a hosted system for production compliance records and should not be used
to store confidential company activity data or credentials.

## Supported versions

| Version | Security updates |
| --- | --- |
| 0.1.x | Supported on a best-effort basis |
| Earlier versions | Not supported |

## Reporting a vulnerability

Please report suspected vulnerabilities privately through
[GitHub Security Advisories](https://github.com/Ting-En-Chien/carbon-evidence-ledger-tw/security/advisories/new).

Do not disclose a suspected vulnerability in a public Issue, Discussion, pull
request, or screenshot.

Include only the information needed to reproduce and assess the problem:

- affected version or commit;
- affected component or page;
- clear reproduction steps;
- expected and observed behavior;
- potential impact;
- a suggested mitigation, if available.

Remove access tokens, passwords, personal information, and real company data
before submitting the report. Use synthetic examples whenever possible.

## Response process

This project is maintained on a best-effort basis. The maintainer will aim to:

1. acknowledge a complete report within seven days;
2. assess reproducibility, severity, and affected versions;
3. coordinate a fix and disclosure timeline when the issue is confirmed;
4. publish an update or mitigation note when appropriate.

Please allow a reasonable remediation period before public disclosure.

## Security boundaries

The public Streamlit deployment is a demonstration environment. Users remain
responsible for removing confidential information before uploading files. The
project does not provide legal, assurance, customs, or regulatory-compliance
advice, and a security report should not be used to transmit production data.
